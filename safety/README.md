# safety

Defense-in-depth advisories and extension guards for OMP.

## Rules (TTSR)

- `srobroek-attribution-guard`
- `srobroek-bash-indirection-guard`
- `srobroek-git-force-push-advisory`
- `srobroek-package-investigate`
- `srobroek-remote-exec-guard`
- `srobroek-sudo-destructive-advisory`

The blocking guards, `srobroek-bash-indirection-guard` and `srobroek-remote-exec-guard`, share a test corpus. `bun test rules/` scores each case against the `condition` in the rule's frontmatter. It checks both encodings carried by a live buffer: bash tool argument JSON and the bare command.

To compare two versions against the same corpus, point `GUARD_RULE_DIR` at another checkout's rules directory:

```sh
GUARD_RULE_DIR=/tmp/before bun test rules/
```

Both guards match only a bash tool call's streaming arguments. They cannot inspect:

- Assistant prose.
- Thinking text.
- Other tools' arguments.
- Tool results.

A later bash argument that quotes tool output can trigger a guard; the original tool result cannot.

## Extensions

- `close-keywords`: rewrite `gh pr create|edit --body` so close-keywords apply to every issue in a list.
- `quality-edit-advisory`: after enough edits, suggest targeted language checks.

Body rewriting accepts only literal shell words and replaces the source span of the selected PR body. Single quotes, apostrophes, and literal dollar signs/backticks remain data.

The extension leaves commands containing expansions or unsupported shell syntax unchanged. For those commands, normalize close-keyword lists explicitly or supply a literal body. The rewrite is not a shell security boundary.

Quality counters are session-local and repository-scoped. Only successful edit results count; the advisory discards failed calls. Restarting or switching sessions resets accumulated files, lines, and the advisory cooldown. The advisory does not share counters through temporary files.

The `srobroek-package-investigate` TTSR rule prompts package vetting before installation, not after the result.

## Hook limitations

- **Commit messages:** OMP has no git commit-msg hook runtime. The plugin rewrites only the `gh pr` path through `tool_call` input rewriting; it does not provide the legacy `hooks-close-keywords` commit-msg rewrite.
- **Pre-tool advice:** OMP cannot inject pre-tool advice without blocking. `quality-edit-advisory` prepends a reminder on `tool_result`. `close-keywords` rewrites the command rather than advising. The `srobroek-package-investigate` TTSR rule provides package-add advice.
- **Pre-commit detection:** The edit handler infers coverage only from checker names in `.pre-commit-config.y*ml`. It does not run `git rev-parse --git-path hooks` or inspect hooks for "generated by pre-commit".
