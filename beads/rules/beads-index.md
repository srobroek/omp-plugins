Beads (`bd`) rules, read on demand via `rule://<name>`:

- `beads-core` — the base contract: claiming, field taxonomy, routing, dependencies, sync authority, and database maintenance.
- `beads-setup` — initialising beads in a repository and verifying the install.
- `beads-lifecycle` — status transitions and gate beads.
- `beads-carriers` — which carrier holds a decision: comment, decision bead, wisp, artifact.
- `beads-composition` — choosing between issue, epic, formula, molecule, bond, wisp.
- `beads-coordination` — swarms, merge slots, and passing a bead id at spawn.
- `beads-orchestration-doctrine` — claim-as-contract doctrine for multi-agent runs.
- `beads-audit` — when a semantic event needs an explicit audit entry.
- `beads-github-mirror` — mirroring beads to GitHub issues.
- `beads-adr` — recording an architecture decision as a decision bead.
